# ADR-006: Project structure, tooling and build configurations

## Status
Proposed

## Date
2026-10-04

## Context
The project is written almost entirely by AI coding agents and will be published as open source.
That raises four requirements:
- **Agent-editable project configuration.** Hand-editing `project.pbxproj` is error-prone for agents
  and produces noisy diffs.
- **Fast feedback.** Most logic must be testable without launching a simulator.
- **Easy contribution.** Contributors must be able to build and run without the maintainer's Apple
  Developer Team, which is needed for iCloud, App Groups and keychain sharing.
- **One app for iPhone, iPad and Mac** (ADR-001).

A probe on this machine (XcodeGen 2.46, Xcode 26.2) confirmed one application target with
`supportedDestinations: [iOS, macOS]` builds for the iOS Simulator and macOS. It also confirmed that
a local Swift package can be linked into that target.

## Decision
- **XcodeGen.** `project.yml` is the source of truth. `VocabularyOS.xcodeproj` is generated by
  `xcodegen generate` and is gitignored.
- **Targets:**
  - `VocabularyOS`: one multiplatform SwiftUI application (iOS, iPadOS, macOS).
  - The Share extension, as one target per platform if a single multiplatform extension target
    proves unreliable.
  - UI tests.
- **Logic lives in the local package `Packages/VocabularyKit`.** It has one library product per
  module (`VocabularyCore`, `VocabularyAI`, `VocabularyData`, `VocabularyCapture`,
  `VocabularySpeech`, `VocabularyUI`) and one Swift Testing target per module. `swift test` runs on
  the Mac host because the package's minimum platform is macOS 26. The `vos-eval` executable
  evaluates prompts against the on-device model.
- **Swift settings:**
  - Swift 6 language mode everywhere.
  - In the app target and `VocabularyUI`, default actor isolation is `MainActor`.
  - Other modules are non-isolated and expose `Sendable` types.
- **Signing and entitlements:**
  - `Config/Base.xcconfig` holds shared settings.
  - It optionally includes `Config/Signing.local.xcconfig` (gitignored), where a developer sets
    `DEVELOPMENT_TEAM`, `VOS_BUNDLE_PREFIX` and `VOS_ENTITLEMENTS = Full`.
  - Without that file:
    - builds are ad-hoc signed;
    - the `Local` entitlements are used (sandbox, network client, camera, user-selected files);
    - the app runs with local storage only.
  - `Full` adds iCloud (CloudKit, key-value store), push, the App Group and the keychain access
    group.
- **No third-party runtime dependencies.** Adding one is an "ask first" boundary in the spec.
- **`scripts/verify.sh`** is the single gate, run before each commit. It runs `xcodegen generate`,
  then `swift test` for the package, then `xcodebuild` for iOS Simulator and macOS. It fails on any
  error.

## Alternatives Considered
- **Committing a hand-maintained `.xcodeproj`:**
  - No extra tool, but merge conflicts and fragile agent edits.
  - Rejected.
- **Tuist:**
  - More powerful (caching, modules as targets), but heavier, with Swift manifests and its own
    workflow.
  - Rejected as more than this project needs.
- **Separate iOS and macOS app targets:**
  - Duplicated settings and resources.
  - Rejected now that multiplatform targets are supported and verified.
- **Logic in app targets only:**
  - Tests would need a simulator, which is slow.
  - Rejected.

## Consequences
- Contributors need XcodeGen (`brew install xcodegen`). The README says so.
- Agents edit YAML and Swift files only, which gives reviewable diffs.
- The package's minimum platform (macOS 26) means `swift test` needs a Mac running macOS 26, which
  matches ADR-001.
- Two entitlement flavors must be kept in sync whenever a capability is added.
